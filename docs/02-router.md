# 意图路由矩阵：让"该读什么"变成查表

> 常规的文件索引只回答"这个文件是什么"。路由矩阵多一列，回答**"什么时候该读、什么时候不该读"**。

---

## 一、为什么需要

有了一堆文件后，Agent 面临选择：用户说了句话，该读哪几个？

- 不读：信息不足，答非所问
- 全读：上下文爆炸，注意力稀释

**路由矩阵把这个选择从模型自由裁量，变成查表。**

---

## 二、表格结构

五列，缺一不可：

| 意图 / 场景 | 触发时机 | 第一优先级必读 | 第二优先级关联 | 预期产出 |
| :--- | :--- | :--- | :--- | :--- |

### 各列的作用

| 列 | 作用 | 不写会怎样 |
| :--- | :--- | :--- |
| **意图 / 场景** | 用户可能怎么说 | Agent 匹配不上 |
| **触发时机** | **什么时候该调用** | 不知道该主动读还是等指令 |
| **第一优先级必读** | 最少必要文件集 | 读太多或读太少 |
| **第二优先级关联** | 按需补充 | 缺上下文时不知道去哪补 |
| **预期产出** | 读完要交出什么 | 读完不知道干什么 |

**"触发时机"是灵魂。** 它让 Agent 知道边界，而不是无限加载。

---

## 三、示例（通用形态）

| 意图 / 场景 | 触发时机 | 第一优先级必读 | 第二优先级关联 | 预期产出 |
| :--- | :--- | :--- | :--- | :--- |
| **会话启动 / 接手项目** | 每次新会话、断点恢复 | `AGENTS.md`<br>`状态中枢.json` | `ROUTER.md` | 确认当前阶段与活跃事项 |
| **进度核对** | 用户问"现在到哪了" | `状态中枢.json` | 对应模块的 `01_计划/` | 给出或静默更新进度 |
| **深入某模块** | 用户点名某个模块 | 该模块 `README.md` | `01_计划/` → `02_考点/` | 加载最小必要集 |
| **新建文档** | 任何产生新文件的动作 | `docs/03-file-protocol.md` | `tools/verify_workspace_links.py` | 完成五步闭环 |
| **遇到重复报错** | 踩到以前踩过的坑 | `02_运行规则/避坑账本.md` | 相关补丁编号 | 修复并考虑入账 |
| **规则冲突** | 两条规则打架 | 协作协议「冲突处理」节 | — | 按更晚的为准，不问 |

## 四、写法纪律

### 1. 一行一个场景，不要合并

"学习"和"新建文件"是两个场景，触发条件和必读文件都不同。合并了就查不准。

### 2. 第一优先级控制在 1～2 个文件

超过 3 个说明这个场景该拆。

### 3. 用相对路径，不用绝对路径

绝对路径换台机器就废。所有路径相对工作区根。

### 4. 定期清理失效行

场景消失了（项目阶段过去），对应行要删。**路由表腐烂比没有更糟**——Agent 会照着走死链。

## 五、与文尾网格的分工

| | 路由矩阵 | 文尾网格 |
| :--- | :--- | :--- |
| 方向 | Top-Down（中枢统一维护） | Bottom-Up / 横向（每个文件自带） |
| 回答 | 用户说了X，读哪些 | 我在这个文件，还能去哪 |
| 位置 | 一个文件（`ROUTER.md`） | 每个 Markdown 文尾 |
| 维护成本 | 集中，改一处 | 分散，但随文件创建自动生成 |

两者互补：矩阵给主干，网格给分支。详见 [03-file-protocol.md](03-file-protocol.md)。

---

## 六、常见错误

| 错误 | 后果 | 修正 |
| :--- | :--- | :--- |
| 只有"文件清单"没有"触发时机" | Agent 不知道该主动读还是等 | 补上时机列 |
| 一行塞多个场景 | 查表查不准 | 拆行 |
| 第一优先级列了 5 个文件 | 等于没路由 | 拆场景或砍文件 |
| 写绝对路径 | 换机器全废 | 相对路径 |
| 失效行不清理 | 照死链走 | 定期清理 |
