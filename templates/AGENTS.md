# AGENTS.md — 工作区自动发现与渐进披露总入口

> 本文件是 Agent 进入本工作区的**首屏自动发现入口（L0）**。
> **核心原则**：保持极其精简（≤ 90 行），只保留环境事实、指针与不可动摇的硬约束；业务细节一律**渐进披露**，按需调阅。

---

## 一、本机环境基线（按你的实际情况改写）

- **操作系统与终端**：`<Windows 11 / macOS / Linux>`；工作区路径含中文与空格时，终端传参**必须加引号**。
- **语言运行时**：`<Python 3.x 路径>`、`<Node vX>`。
- **不可用工具**：`<例如：未安装 Pandoc，禁止调用 pandoc 命令>`。
- **格式转换**：外部文档（docx/pdf/xlsx）统一用 `tools/convert_to_markdown.py`。

> 这一节的价值在于"什么是不真的"。写清楚本机**没有**什么，能避免 Agent 反复盲目试错。

---

## 二、启动时必须按序执行

1. **第 1 步：查状态** → `01_状态中枢/状态.json`
   - 确认当前阶段（`current_phase`）、活跃事项与薄弱模块。
2. **第 2 步：找路线** → `ROUTER.md`
   - 依据当前意图，查"意图 → 触发时机 → 必读文件"表，定位最小必要文件集。
3. **第 3 步：守纪律** → `00_协作协议.md`（按需查阅，不必全读）
4. **第 4 步：切领域** → 进入对应 `03_资料库/{领域}/`

---

## 三、不可动摇的核心硬约束

> 编号制，每条一句话。新增约束就追加编号，不要重排。

1. **纯目标交互**：禁止角色扮演、客服口吻、元分析汇报。第一句话直接切入实质。
2. **结构化提问**：关键分叉点禁止散文发问，必须给 2～4 个互斥选项，推荐项置首。
3. **先读后改**：声称检查过某文件前必须真的读过；结论必须带证据（路径/行号/数值）。
4. **会话隔离**：「使用」与「改造规则」分开，避免角色分裂与上下文污染。
5. **防孤岛文件**：新建任何 Markdown 必须完成五步闭环（见 `docs/03-file-protocol.md`），并跑 `tools/verify_workspace_links.py`。
6. **全量归档**：外部权威文件第 0 步先无损转存，禁止只做临时抽取。
7. **根目录防污染**：产出物就地归档，禁止往根目录抛洒零散文件。
