# 全局全景路由与时机调度矩阵（ROUTER.md）

> 本文件是工作区的**中枢交通地图**。
> **核心原则**：不把海量资料一次性灌入上下文（防止 Context Rot 与注意力稀释），而是依据意图、阶段与当前薄弱点，**按需、渐进、精准加载**最小必要文件。

---

## 一、渐进式披露路由机制说明

工作区将知识与规则划分为四级梯次，遵循"按需逐步展开，文尾辐射下级"的双向链式机制：

```text
┌────────────────────────────────────────────────────────┐
│  【L0 入口层】 AGENTS.md                                │
│  极简指针 + 启动必读序列 + 渐进披露协议                    │
└──────────────────────────┬─────────────────────────────┘
                           ▼
┌────────────────────────────────────────────────────────┐
│  【L1 状态与调度层】 01_状态中枢/ + ROUTER.md           │
│  当前阶段/掌握矩阵 + 意图场景与文件精准映射表             │
└──────────────────────────┬─────────────────────────────┘
                           ▼
┌────────────────────────────────────────────────────────┐
│  【L2 规则与底座层】 00_协作协议.md + 02_运行规则/      │
│  交互纪律 + 经验沉淀补丁 + 新文件联动闭环规范             │
└──────────────────────────┬─────────────────────────────┘
                           ▼
┌────────────────────────────────────────────────────────┐
│  【L3 领域层】 03_资料库/{领域}/...                     │
│  01_计划 ──(文尾辐射)──> 02_核心考点 ──> 03_题型模板     │
└────────────────────────────────────────────────────────┘
```

### 两种互联机制的协同运行

1. **中枢路由表（Top-Down）**：由本文件维护意图到文件路径的宏观映射；
2. **文尾网状辐射（Bottom-Up & Lateral）**：**每一个 Markdown 文件文尾均配置标准化《关联文件与引用时机网格》**，明确指出目标文件路径、核心内容、引用时机与关联属性。一旦打开任何文件，绝不会遇到"死胡同"，可自然沿链条展开。

## 二、意图 → 触发时机 → 核心文件路由表

> **改写说明**：下表是结构示例。请把「意图」「必读文件」换成你自己领域的实际内容。
> **纪律**：一行一个场景；第一优先级控制在 1～2 个文件；路径用相对路径。

| 意图 / 场景 | 触发时机（何时调用） | 第一优先级必读文件 | 第二优先级关联文件 | 关键目标与预期产出 |
| :--- | :--- | :--- | :--- | :--- |
| **会话启动 / 接手项目** | 每次新会话开始、断点恢复或用户发出第一条指令 | `AGENTS.md`<br>`00_协作协议.md` | `01_状态中枢/状态.json` | 确认定位、交互纪律、当前阶段与活跃事项 |
| **进度核对与打卡** | 用户问"现在到哪了""这周该做什么""更新进度" | `01_状态中枢/状态.json` | `ROUTER.md`<br>对应领域 `01_计划/` | 获取或静默更新 `current_phase` 与 `matrix` |
| **深入某领域** | 用户点名某个领域或模块 | 该领域 `README.md` | 该领域 `01_计划/` → `02_考点/` | 按"计划 → 考点 → 模板"顺序加载最小必要集 |
| **重难点攻坚** | 涉及具体难点、大题、核心机理 | 该领域 `01_计划/` | 该领域 `02_考点/`、`03_题型模板/` | 拆解为可执行的步骤流水线 |
| **新建文档或模板** | 任何产生新考点卡、解法、解析的操作 | `00_协作协议.md`（新文件联动协议）<br>`docs/03-file-protocol.md` | `tools/verify_workspace_links.py` | 严格执行五步闭环（Frontmatter、文尾网格、父级登记、上游回填、中枢挂载） |

| **执行环境命令与脚本** | 准备调用 CLI、运行脚本或在终端传参时 | `AGENTS.md`（环境基线）<br>`02_运行规则/避坑账本.md` | `tools/` 工具源码 | 核对本机真实能力，杜绝盲目试错 |
| **错误复盘与规则沉淀** | 发生新的共性痛点需要固化规则时 | `02_运行规则/避坑账本.md` | `docs/04-failure-ledger.md` | 执行三不录原则与超密微卡格式 |
| **输入/上传新文件** | 用户上传或提供 docx、pdf、xlsx 等原始文件 | `02_运行规则/避坑账本.md`（全量归档补丁）<br>`tools/convert_to_markdown.py` | 对应领域 `00_原始文献/README.md` | **第 0 步强制**执行全量无损转 .md 并归档挂载 |
| **关键决策分叉** | 遇到阶段完成、难度分档、路线选择等节点 | `00_协作协议.md`（结构化提问节） | 无（立即调用工具） | **禁止散文反问**，必须显式调用结构化提问 |
| **语音输入容错** | 用户使用语音输入导致同音错字、倒装、断句缺失 | `00_协作协议.md`（语音容错节） | 对应领域考点卡 | **严禁错误回音壁与挑刺**，后台静默重构真实语义 |

## 三、各领域资料库调用链与拓扑规范

各领域内部严格按四级目录层级流动，且层级间必须建立明确的前后向指针：

```text
03_资料库/{领域名称}/
  ├── README.md                       # 领域总路由（说明范围、目标与子模块）
  ├── 00_原始文献与课程文件/
  │     ├── README.md                 # 原始文件索引（全量无损转化后的归档库）
  │     └── {原始文件名称}.md          # 权威依据全量无损副本
  ├── 01_计划/
  │     └── {领域}_全景方案.md         # 顶层纲领：阶段表、目标、各章 MST
  ├── 02_核心考点/
  │     └── 第X章_{主题}_核心考点卡.md  # 微观机理：图像、公式前提、易混淆辨析
  └── 03_题型模板/
        └── {题型}_{考点}_解题流水线.md # 落地：三步解法、步骤分保底、防空卷模板
```

### 跨层级引用规范

1. **01_计划** 的表格中，必须明确引向对应的 **02_核心考点** 与 **03_题型模板**；
2. **02_核心考点** 顶部声明上游计划，文尾引向对应的 **03_题型模板**；
3. **03_题型模板** 顶部声明前置核心定理，文尾引向巩固练习或状态中枢更新。
